# SyncCloud 可靠性修复记录（2026-11-17）

本轮针对立即同步无反馈、阿里云盘同步失败，以及同步调度、持久化和数据保护中的已复现问题。保留现有任务、同步方向、基线和根目录内部的 `.synccloud` 布局；新增排除规则仍会清理对应云端副本，删除保护继续生效。

## 问题与修复

| 问题 | 修复行为 |
| --- | --- |
| 阿里云盘目录 `size: null` 导致远端锁读取报错 | 目录大小接受空值；文件大小未知时查询元数据，仍未知则明确失败，不跳过完整性校验 |
| 空闲监控阻塞异步线程、立即同步看似无响应 | 使用异步事件桥；扫描与哈希移入阻塞任务；命令成功入队才反馈受理，重复请求合并，关闭或满队列返回原因 |
| 配置更新或删除时旧任务继续运行 | 串行管理启动、取消和等待退出；同一任务的同步、恢复、释放空间和冲突处理共用操作锁 |
| 初始化或传输失败后状态不准确 | 初始化可再次尝试；部分失败保留错误；等待替换的文件单独计数和显示，不报告下载成功 |
| 重试退避始终为一秒 | 传输与清单提交使用 1、2、4 秒递增退避，最多 60 秒 |
| 失败上传推进基线，后续可能误删 | 仅推进成功路径；失败、暂停和占用路径保留原基线；成功操作即时写恢复日志 |
| 扫描不完整被当作文件删除 | 根目录、遍历、属性和哈希读取失败均中止扫描；不缓存不可读占位哈希 |
| 变更戳读取失败误命中无变化缓存 | 未知戳不能命中；有恢复日志或待替换记录时完整检查；弱变更戳缺少 ETag 时读取清单验证 |
| 上传期间文件变化导致清单与内容不一致 | 从稳定临时快照上传，校验快照大小与哈希后才传输 |
| 云盘覆盖上传先删除旧版本 | 阿里云盘先完成暂存上传，再发布和删除旧文件；本地恢复记录处理发布中断；百度分片及合并响应必须成功 |
| 阿里云盘真实分片上传签名失败 | 不向 OSS 预签名 PUT 擅自添加 Content-Type，已由真实账户验收复现并验证 |
| 两个任务重复刷新令牌 | 按账户合并刷新，保存轮换令牌成功后才更新内存；认证失败最多刷新重试一次 |
| 上传占用整文件内存或事后限速 | 云盘按块读取，S3/WebDAV 流式传输；限速计入实际传输块 |
| 锁读取失败被忽略、长传输租期过期 | 读取错误传播，定时续租，提交前复核所有权和租期，退出释放 |
| 旧清单迁移提前清理旧数据 | 写新位置并回读完整校验后才清理旧清单，保留其它元数据 |
| 路径越界及 Windows 路径别名 | 校验存储键、清单、本地恢复和占位路径；拒绝导航、设备名及越界链接 |
| 回收站索引竞争、归档失败继续覆盖 | 按任务串行更新索引，验证备份内容；索引或归档失败停止对应动作；冲突恢复用暂存替换 |
| 设置保存竞争、零值丢失、错误无提示 | 串行保存并显示结果；保留重试次数等合法零值；同步参数下一轮生效 |
| 密码和密钥随配置明文保存 | 使用系统凭据管理器引用；旧格式迁移先写入和回读验证，配置写失败仍可恢复 |
| 数据目录迁移丢失 WAL 或忽略复制错误 | 停止并等待任务，排空本地操作；SQLite 一致备份和 integrity_check，其它文件校验哈希；最后提交目录指针，原目录保留，重启生效 |
| 历史加载竞争、事件订阅泄漏 | 过期请求不能覆盖新结果，卸载时清理异步订阅；轮次错误写入历史 |
| Git 失败 push 丢失暂存、删除意图不持久 | 数据与元数据均推送成功后才清理暂存；删除意图跨实例保留；读取和列举错误传播，删除远端分支时清理缓存引用 |
| GNU 构建缓存路径及 WebView2 链接失败 | 统一 Rust 准备脚本，使用 DLL 导入库和运行时 DLL，工作区迁移后清理相关 native 缓存 |
| 同步期间新建或再次编辑的文件被末尾重扫错误确认 | 基线只接收成功动作确认的内容；新增文件和快照后的编辑留给下一轮上传 |
| 满容量回收站恢复会裁剪自己的源备份 | 在索引锁保护下先固定并校验恢复副本，再归档现有工作文件；并发清空不能删除已固定副本 |
| 迁移后待替换记录仍指向旧目录 | 新记录使用相对文件名；旧绝对路径仅按本任务的合法 pending 布局重定位，并校验内容 |
| 删除与更新交错后遗留后台任务 | 统一配置锁到任务生命周期锁的顺序，配置变更和任务停启作为完整事务串行处理 |
| 迁移期间排队的设置或账户保存落入旧目录 | 共享写屏障覆盖配置、账户、授权完成与恢复操作；迁移独占并排空已开始的写入，迁移完成后的排队写入明确拒绝 |
| 先排队、后暂停，再恢复时未实际恢复 | 合并已有请求也完成恢复状态转换，维护检查位于所有成功返回之前 |
| 迁移遗漏 Git 暂存中名为 temp 的业务文件 | 仅排除应用根的临时区和目录指针，嵌套业务目录完整复制 |

## 自动化验证

在仓库根执行：

```powershell
npm test
npm run test:rust
npm run build
npm run build:app
```

前端覆盖按钮受理与拒绝、列表加载失败、设置串行保存、保存失败及零值。Rust 覆盖同步引擎、占用待替换、失败基线、恢复日志、扫描错误、退避、调度队列、凭据迁移、SQLite WAL 备份、回收站并发与越界保护。

后端检查使用本地 HTTP 模拟 S3、WebDAV、阿里和百度；使用本地裸 Git 仓库检查锁、读写删除和 push 失败后的恢复。阿里还覆盖空目录大小、分页、未知文件大小补查、非法分片、中断上传恢复和刷新竞争。百度覆盖缺失目录与权限错误、刷新竞争，以及 HTTP 200 业务错误不得继续合并文件。

失败证据与验证日志保留在被 Git 忽略的 `src-tauri/target/` 中，包括 `reliability-red.log`、`upload-red.log`、`stamp-red.log`、`part-red.log`、`pending-red.log`、`git-red.log`。最终交付目录的 `VALIDATION.md` 记录最终源码与二进制的验证结果及校验值。

## 真实账户验收与边界

`src-tauri/examples/reliability_acceptance.rs` 只读取现有账户，在 `/SyncCloud-acceptance-<UUID>` 创建独立测试目录。显式加 `--live` 才会访问真实云盘；不修改现有任务配置，也不操作 Obsidian 或共享文件任务的同步根。

```powershell
node scripts/rust.js run --locked --example reliability_acceptance -- --live
```

检查 10MB 跨分片上传、下载、内容哈希、覆盖、清单与变更戳、锁和删除，并清理专用目录。异常中断可用 `--live --cleanup-root=/SyncCloud-acceptance-<UUID>` 清理该目录；清理接口拒绝普通用户目录。首轮阿里与百度真实验收均通过，最终版本复验结果随便携版附带。

## 保留和回退

构建前保留旧 `dist-app/synccloud.exe`，新版本输出在同一目录。未停止或替换用户正在运行的程序，未重置任何任务基线。旧启动器及旧运行文件仍保留；退出旧版后运行新便携版才会使用新核心。

凭据引用绑定当前 Windows 用户，复制配置到其它电脑不能自动获得密码。数据目录迁移成功后，旧目录继续保留，直到确认新目录工作正常再手动清理；不要在两个目录间同时运行同步程序。

## 剩余优化与验证限制

- 按当前单电脑使用验收；现有多设备租约增加续租和复核，但不具备跨后端强原子抢锁保证，多设备锁协议重构单独实施。
- Git 通过外部 Git 进程传输对象；精确网络字节限速、所有 Git 子进程的统一硬超时，以及大对象读取进一步流式化仍可优化。
- S3/WebDAV 没有可用的真实授权账户，本轮使用 HTTP 模拟契约；Git 使用本地仓库，不代表所有远端服务商均已真实验收。
- 版本化凭据在配置写入失败时会保留可恢复条目；无引用凭据的自动回收可后续补充。
- 本轮不启动新的 GUI 实例接管现有任务。按钮与状态通过前端回归测试验证，实际桌面显示及现有任务持续运行情况需在用户退出旧版、启动新版后观察。
- 加密功能仍保持未开放状态，没有新增存储后端。
