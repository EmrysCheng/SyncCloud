# 阿里云盘批量上传中的续租错误

用户现象：同步开始后一段时间报“远端锁续租失败，禁止提交清单”，后续轮次继续上传尚未完成的文件。

现场文件日志确认：续租使用的 `/adrive/v1.0/openFile/list` 返回 HTTP 429 / `TooManyRequests`，提示等待 84 或 294 毫秒。原实现没有限流重试，也没有跨同步根共享的账户请求频率控制，单次临时限流随即把租约标为丢失。清单提交保护本身仍需要保留。

修复：同一账户的控制 API 请求共用至少 100 毫秒的发信间隔与冷却窗口；429 或明确 `TooManyRequests` 响应遵守 `Retry-After`（秒数或 HTTP 日期）及响应消息中的毫秒提示，并采用 250/500/1000/2000 毫秒递增退避，最多重试 4 次。排队和重试受请求发起后 20 秒墙钟预算约束（包含先前认证与响应耗时），单次网络请求仍有独立的 30 秒超时。超出局部预算的响应仍更新账户共享冷却，超大等待值使用受检时间运算。OSS 文件上传不受控制 API 频率限制。认证失效仍最多刷新重试一次；未对不确定是否已执行的普通服务端错误自动重放写操作。

长时间真实验收另观察到下载 403。下载重试现在重新申请签名链接，并仅记录安全的 HTTP 状态与 CDN 错误码，不输出签名 URL；新增模拟回归已复现原实现始终重用失效链接的问题。具体真实 403 的发生阶段及复验结果以验收日志为准，不把模拟回归直接当成真实根因证明。

全量回归还实际捕获下载成功返回后立即读取到空文件的竞态：Tokio 文件写入缓冲尚未完成。下载现在在返回成功或重试覆盖之前 flush 并关闭句柄，确保元数据回读和内容哈希读取已完成落盘的字节。

真实失锁、过期、所有权变化和重试耗尽仍阻止提交清单。轮次已完成动作的恢复日志继续保留，未清空现有任务基线。

新增回归在修复前实际变红：临时 429 立即失败，同账户两个同步根并行请求没有共享频率预算。修复后覆盖服务端等待提示、并发限频、持续限流有界退出、限流后的单次认证刷新、超大 Retry-After 拒绝等待，以及失锁/过期仍拦截提交。
